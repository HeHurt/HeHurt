# 海辰仿真秘籍编写

编写前先阅读 [模板标准](references/template_standard.md)。这是一套低自由度的部门交付规范：版式必须复用 F413，内容可以随课题变化。

## 0. 先确认范围

在写代码、修改模型、运行仿真或生成图前，向用户简要说明：课题边界、拟采用的模型/数据/对话演进记录、计划生成的图，以及 2–3 条可验证验收标准；等待批准。需求缺少电芯、参数、工况、模型版本或数据时，先查现有任务包、运行记录和 registry；仍不能确定的，列为待确认项，不擅自选值。

## 1. 锁定模板与任务包

1. 使用 `documents` skill 处理 `.docx`，并遵守项目 DLP 规则：先由白名单 Python 生成临时明文副本，确认 `PK\x03\x04` 与 `zipfile.is_zipfile(...)`；若失败，改用 Word 原生 COM，不得使用 `Code.exe` 文本桥读取 Office 容器。
2. 每次从标准中指定的 F413 文件复制一份到当前任务包后再编辑，记录其 SHA-256。不要自建空白 Word、重画模板，也不要把模板副本放进本 Skill 形成第二真源。
3. 模板不可读取、哈希不一致或用户要求另一份模板时，暂停并请求用户确认；不要以“相似格式”替代。
4. 新任务先运行 `python tools/task_delivery.py new-task ...`，在 `work/<体系>/YYYYMM_何争_<课题>V1/` 建包。报告放 `01_仿真报告/`，可审计模型/脚本放 `02_模型/`，输入放 `03_输入数据/`，图和发布结果放 `04_输出结果/`，复现步骤放 `05_复现说明/`。

## 2. 以证据组织内容

先做只读盘点，再按实际技术路线取证：

- **PyBaMM/BatteryProject**：检查 `BatteryProject/src/` 的函数、参数与调用链；涉及电解液干涸、老化、DCR 或生命周期时，使用 `hithium-pybamm-debugging` skill。
- **COMSOL**：盘点 `.mph`、Desktop 导出的 `.m`/`.java`、参数表、求解设置、模型快照、运行日志和后处理结果；用对应的 COMSOL skill 读取、另存、运行与验收。DLP 包装的 `.mph` 以 COMSOL 原生加载结果为准，不以离线 ZIP 解析失败判定模型不可用。
- **GPT 多轮迭代功能**：把每轮有效决策整理成可审计演进链：基线模型版本/哈希 → 对话提出的假设或改动理由 → 实际修改的节点、参数或脚本 → 保存后的版本 → 运行或后处理证据。对话记录只用于解释“为何这样改”；没有落到模型并运行的内容仍是待验证设计，不是结果。
- 实验数据需要时先查 `datasets.json`/`data_registry.py`，不要从 `data_raw/` 猜文件名。
- 区分“已由代码验证的机制”“待运行的模型预测”“待实验验证的假设”。没有已完成 run、工况和原始数据时，图表和结论必须标为“待运行/待验证”，不得补造数值、曲线、RRMSE 或失效循环数。
- 公式、流程图、参数表和结论均能追溯到 Python 函数、COMSOL 节点/单位、导出脚本、参数、数据、运行记录或对话演进台账；为图给出计算/后处理脚本与输入说明。

## 3. 保持 F413 的文档结构和视觉语法

保留模板已有的封面、编制说明、目录、页眉页脚、标题级别、表格和章节编号规则。内容按模板的同一叙事顺序展开；通常为：技术背景与目标、模型与机制、工况/参数、实施方法、后处理与结果、交付与适用边界。仅在课题确实需要时新增章节，且仍使用模板的标题层级与表格样式。

- 不更换页面尺寸、边距、字体、封面构图、页眉横线、页码或编号体系。
- 图表使用真实仿真输出，或由项目代码生成的、明确标注为“机理示意/流程示意”的图；图片置于图题前，图题和表题沿用模板编号与排版。
- 采用正式、可审计的中文工程表述。机制解释写清假设、适用范围和失效边界；避免宣传性套话。

## 4. 交付前必须验收

1. 在 Word 中更新目录、交叉引用和页码字段；最终文件为 `.docx`，除非用户另要 PDF。
2. 用 `documents` 的渲染流程生成 PDF/逐页 PNG；若 `soffice` 不可用，使用 Word COM 导出临时 PDF 后继续渲染。逐页检查封面、目录、正文、页眉页脚、表格、图片、图题和分页，发现截断、重叠、空目录、编号错乱或样式漂移必须修复后重验。
3. 将最终模型快照、脚本、生成图片、输入清单、对话演进台账和 README/复现说明归档在同一版本任务包；COMSOL 模型必须保留 baseline 与本任务版本，禁止覆盖成功源模型。临时 PDF、渲染图和工具中转文件不作为正式交付物保留。
4. 交付时说明：最终 Word 路径、模板哈希、实际运行/未运行的范围、每张图的来源，以及尚需用户补齐的图或数据。

## 禁止事项

- 禁止把无数据的示例曲线包装成仿真或实验结果。
- 禁止把 GPT 对话中的推断、计划或“已修改”表述当成实际模型运行结果；需要给出落盘版本和运行证据。
- 禁止只模仿封面或字体而不复用 F413 的章节、页眉页脚和编号体系。
- 禁止覆盖已上传任务版本；返修新建 V2/V3。
- 禁止为了“写全”而修改 `BatteryProject/src/`、COMSOL 源模型、参数或原始数据；模型变更需是用户明确授权的独立实现任务，并按对应项目测试协议验证。
