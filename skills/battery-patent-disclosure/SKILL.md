# 电池方向专利技术交底书生成 (Battery Patent Disclosure)

为电池研发发明生成一份**可直接提交、排版专业的中文专利技术交底书**：遵循海辰储能（Hithium）交底书模板，正文楷体、A4，内嵌 **5 张黑白专利风格附图**，输出 `.docx`。本 skill 固化自多份交底书（贯穿方向梯度孔隙率电极 / 极耳变宽焊印 / 集成电解液储液浸润结构 / AI Agent 老化模型自动选型与标定）打磨出的流程与经验。

- 专利工程师：留空
- 创新方式：☒ 自行研发
- 字体：全文**楷体**（KaiTi）；页面 A4，页边距 1 英寸
- 申请人语境：**海辰储能**，长时储能，LFP/石墨，厚涂层电芯（写"现有技术"和"技术效果"时可默认此背景）

## 何时使用
见上方 description。核心信号：用户给出一个电池相关的发明点子并希望写成专利/交底书；或直接说"写一个 XX 的专利交底书"。

## 工作流程（按顺序执行）

### 0A. 批量头脑风暴 / 候选初筛入口
当用户说"帮我想几个专利"、"再多想一些结构/工艺类"、"先初筛一遍"、"去掉拥挤度高的"时,不要直接写交底书。先输出候选池:

1. 按方向分组: 结构、工艺、测试/诊断、仿真/算法、BMS/运维。
2. 每个候选给: 核心发明点、可保护对象、为什么适合海辰长时储能、可能相近技术、拥挤度初判(高/中/低)、建议下一步。
3. 优先推荐"问题真实、可测可验证、结构或流程边界清楚、与长时 LFP/石墨厚电芯相关"的方向。
4. 对拥挤度高的候选,只保留差异化切入点;不要把普通注液、常规压力管理、泛泛 AI 预测写成强候选。
5. 用户选定某个候选后,再进入 Step 0/1 的正式交底书与 prior-art 初筛流程。

批量查新时,先生成脱敏中文检索式、关键词组合、分类号和候选排序表;只有用户提供度衍导出或授权后,才分析具体度衍结果。

### 0. 判定类型
判断是**结构类**（电极/极耳/焊接/卷绕/注液/电芯结构等可见可测的硬件改进）还是**软件/方法类**（仿真方法、算法、BMS 逻辑、寿命建模等）。多数电池发明是结构类。软件/方法类需要做客体合规处理（见策略参考）。在文档标题副标注相应写 `（结构类）` 或 `（软件 / 方法类）`。

### 1. 先做现有技术初筛（先读 `references/prior_art_screening.md`）
**动笔前先跑一轮 prior-art 初筛，尤其是用户提到"查重/查新/度衍/重复专利/FTO"时必须执行。** 按 `references/prior_art_screening.md` 处理：先生成脱敏检索式、分类号和中英文关键词；再根据可用条件选择公开 web 检索、度衍官方 API（仅在用户提供授权和文档时）、度衍浏览器半自动检索或度衍导出结果分析。对话里给用户：**拥挤度（高/中/低）+ 命中的相近在先技术（paraphrase 并引用来源）+ 差异化建议 + 可直接粘进度衍的中文检索式与分类号**。命中过近时，先和用户确认是否**调整切入点或换方向**，再决定动笔；决定写时把最接近对比文件与差异点喂进"现有技术/缺陷"铺垫与"改进点"，使权利要求落在空隙上。固定提示三条：**初筛非正式 FTO、度衍/中文库需复核、非法律意见**。

### 2. 策略与可行性判断（先读 `references/strategy_and_eligibility.md`）
**动笔前**先快速判断可行性、定下权利要求策略，并在对话里给用户一段简短的可行性说明。要点（细节见参考文件）：
- 优先**结构权利要求**（拆解/CT 可见可测，比纯算法强）；
- 机理方向有争议时用**功能性/目标导向**的权利要求措辞；
- 软件/方法类必须**绑定硬件 + 技术问题 + 技术效果**以越过中国"智力活动规则"客体门槛，并配套**系统 + 计算机可读存储介质**权利要求；
- 把"**设计判据（仿真给出）**"与"**受保护对象（落入界定范围的结构）**"切分开——保护结构，不保护算法；
- 收尾务必提示 **FTO（自由实施）检索**、参数为**示意值需仿真/实测标定**、以及**非法律意见**。

### 3. 先读 docx 技能
构建 `.docx` 前，先 `view /mnt/skills/public/docx/SKILL.md`（环境约束、构建方式）。

### 4. 生成 5 张附图（先读 `references/figure_guide.md`，用 `assets/fig_helpers.py`）
标准 5 张：① 结构示意图（截面/俯视，带数字标号）；② 对比曲线（现有=虚线，本发明=实线）；③ 机理示意（或机理↔可观测特征映射表）；④ 制造流程图 S1–S5（结构类）或系统架构图（软件类）；⑤ 技术效果/外推曲线。
- 全部**纯黑白**；用 `fig_helpers.setup_cjk()` 注册中文字体（Noto Sans CJK）。
- **每张图生成后必须 view 检查**并修正：标注重叠、箭头方向、缺字形（坑见参考文件）。把 PNG 存到工作目录（如 `fig/f1.png`…`fig/f5.png`）。

### 5. 构建 .docx（用 `assets/build_jiaodishu.js`）
把 `assets/build_jiaodishu.js` 复制到工作目录，填写文件顶部 **CONTENT 区**：标题类型、提案名称、技术领域、缺陷条目、方案 A/B/C、技术效果（推理式）、改进点 1–5，以及 5 张图的 `img()` 调用。联系人、楷体、A4、表格均已内置。若环境无 `docx` 包则 `npm i docx`（通常已全局安装）。

### 6. 校验与预览
- 校验：`python3 /mnt/skills/public/docx/scripts/office/validate.py <file>.docx`
- 预览：用 `soffice.py` 转 PDF → `pdftoppm` 转图 → `view` 看 1–2 页，修排版。
- 注：预览环境可能没有楷体而用替代字体显示，**在用户的 Windows Word 里会正确显示楷体**。

### 7. 交付
`present_files` 输出 `.docx`。若执行了初筛，另输出或在对话中给出 `prior_art_search_queries.md`（度衍检索式/分类号/关键词）和 `查新风险初评.md`（相近文件、差异点、风险等级）。对话里给：简短的设计亮点说明 → FTO/参数示意/非法律意见三条提示 → 主动提出可展开为**权利要求草稿**。

## 模板结构（完整规范见 `references/template_structure.md`）
一、基本信息（表格） ／ 二、技术内容〔1 现有产品技术情况；2 现有产品存在的技术缺陷或问题（分条编号）；3 详细技术方案（附图说明 + 附图主要标号；3.1 方案A【最优】；3.2 方案B【拓展】；3.3 方案C【另一拓展】；3.4 改进后的技术效果——推理式）〕／ 4 发明构思总结（表格，改进点 1–5）。

## 关键约定 / 已踩过的坑（不要重新学）
- **动笔前先做现有技术初筛**（见 `references/prior_art_screening.md`）；用户提到度衍/uyanip/查重/查新/FTO 时必须执行；命中过近先与用户确认是否调整切入点或换方向，避免写一份注定撞车的交底书。
- **度衍接入不要臆造 API**：只有用户提供官方 API 文档/授权时才调用 API；否则用脱敏检索式 + 浏览器半自动检索或人工导出结果分析。不要绕过登录、验证码、频率限制或批量抓库。
- **保密优先**：未申请前不要把完整技术交底书上传第三方平台；优先用关键词、分类号、核心特征组合等脱敏检索式。
- **3.4 技术效果必须写成推理链**"①因…→因此…"，不能只下结论（模板明确要求"有理有据、切忌只下结论而无分析"）。
- **方案 A = 最优方案；B、C = 拓展方案。**
- **附图**：纯黑白；写 `dV/dQ` 不要用 Unicode 上标减号（`⁻` 字体缺字形）；下标用 mathtext `$_0$`；箭头方向 = `annotate(xy=箭头头, xytext=箭尾)`（流程图向下别画反）；标题用 `pad`/`ylim` 与图形拉开；曲线易挤就用上下分栏；**每张图都要 view 后修**。
- **docx**：A4（11906×16838 DXA），页边距 1440，正文宽 9026 DXA；基本信息表用 `columnSpan` 合并；字体对象 `{ascii:"Times New Roman", eastAsia:"楷体"}`。
- **3.1 里把"设计判据（仿真）"与"受保护对象（落入界定范围的结构）"分开写**，保护结构不保护算法。
- 对话**结尾固定给三条**：FTO 检索、参数为示意需标定、非法律意见。
