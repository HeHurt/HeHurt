# Hithium PyBaMM核心代码包范围说明

## 结论

完整工作区不适合直接跨机复制。真正的 PyBaMM 核心代码、参数、测试、canonical examples、历史工作流源码、项目规则和 Skills 已汇总为：

`04_输出结果/Hithium_PyBaMM_Core_Code_and_Workflows.zip`

最终压缩包约 3.57 MB；与长期记忆包合计约 4.50 MB，可作为最小迁移集。

## 已包含

- 根目录 `AGENTS.md`、`.gitignore`、`.gitattributes`、`datasets.json` 和环境入口。
- `BatteryProject/src` 核心仿真代码。
- `BatteryProject/api`、`studio`、`deploy` 和启动入口。
- `BatteryProject/tests`。
- `BatteryProject/examples` canonical notebooks。
- `BatteryProject/pyproject.toml` 与 `uv.lock`。
- `params` 全部参数代码及 OCP/扩散等查表文件。
- `tools`、`docs`、`.plans`、项目 `.codex` 配置。
- 项目自定义 `skills`，不包含可重建的 `.system` skills。
- `work` 下的 `.py/.ipynb/.md/.yaml/.json/...` 工作流源码与任务 manifests。

## Notebook处理

原Notebook不修改。归档副本保留：

- code cells；
- Markdown cells；
- notebook/cell metadata；
- 工作流结构。

归档副本清除：

- cell outputs；
- execution count；
- widget state。

70个Notebook执行了该瘦身，83个DLP文件通过VS Code白名单读取。一个源Notebook本身为0字节，已在manifest中明确跳过：

`work/314Ah/notebooks/diff_temperature/不同温度循环/自动提取数据.ipynb`

## 未包含

- `.git`历史；
- `.venv`、缓存和运行时；
- `data_raw`、`data_processed`；
- `BatteryProject/output/runs` 和 Studio运行状态；
- `work/**/04_输出结果`；
- Excel/PPT/PDF、历史图片和大型实验数据；
- COMSOL、archive及其他非PyBaMM资产。

因此，本包可恢复代码和工作流，但实验对标时仍需根据 `datasets.json` 单独迁移对应数据。建议按具体电芯/任务选择数据，而不是再复制完整数据池。

## 验证结果

- 803个项目文件成功归档。
- 归档内无 `%TSD-Header-###%` 密文成员。
- ZIP完整性测试通过。
- 所有归档Notebook均为有效JSON且无历史outputs。
- `BatteryProject/src` 与 `params` 中Python源码语法检查通过。
- 必要文件和 `datasets.json` 均存在且可解析。
- 唯一跳过项为源端0字节Notebook，不是迁移读取失败。
