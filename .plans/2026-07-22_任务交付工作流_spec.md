# 2026-07-22 任务交付工作流 Spec

## 目标

把 BatteryProject 的长期代码、运行时原始产物和可直接上传的任务交付包分开管理，并让新任务从创建开始就进入标准目录，不再在计算结束后手工拼装文件。

## 目录职责

- `BatteryProject/examples/`：canonical Notebook 模板，只复制、不针对单次任务直接修改。
- `BatteryProject/src/`：可复用核心逻辑。
- `BatteryProject/output/runs/`：带 `run_id` 的原始运行产物。
- `BatteryProject/output/studio/`：Studio 数据库、job 和 project 状态。
- `work/<cell>/<YYYYMM_何争_任务名称Vn>/`：可直接上传的任务交付包。

## 任务包内容

```text
00_任务说明.md
01_仿真报告/
02_模型/
03_输入数据/
04_输出结果/
05_复现说明/
task_manifest.json
```

## 工具入口

- `new-task`：创建任务包，可从 `BatteryProject/examples/` 复制一个模板 Notebook。
- `publish-task`：从 `BatteryProject/output/runs/<run_id>/` 发布结果快照到任务包，不移动或覆盖原 run。

## 安全约束

- 已存在的任务目录和已发布 run 目录禁止覆盖。
- `publish-task` 的任务目标必须位于 `work/`，run 来源必须位于 `BatteryProject/output/runs/`。
- 默认发布常用报告、图表、表格、配置与日志；`--mode full` 才复制全部文件。
- 历史 `output/outputs/results` 在归属未确认前只生成迁移清单，不批量移动。

## 验收

- CLI 能建立标准任务包并复制模板。
- CLI 能发布 selected/full 两种结果快照，且原始 run 保持不变。
- 重复任务目录、重复发布和越界路径均被拒绝。
- manifests 记录任务信息、模板来源、Git 状态、run 来源和文件 SHA-256。
